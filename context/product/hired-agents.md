# Specialist Agents Coverage

Generated by hand on 2026-10-09 during the AWOS 1.5.0 upgrade (the equivalent of a `/awos:hire`
run with the registry gates answered "not now"). The `awos-recruitment` MCP
(`https://recruitment.awos.provectus.pro/mcp`, registered in `.mcp.json`) was queried over HTTP
(`search_capabilities`) and two skills were installed with
`npx @provectusinc/awos-recruitment skill <name>`: **`verify-ui` 1.0.0** (Playwright-MCP DOM
checks, the same skill Citation's QA agents bind) and **`gha-diagnosis`** (GitHub Actions failure
triage, for the new CI gate). Registry probes that came back empty — so these gaps cannot be
filled from the registry by anyone: no Go skill or Go agent exists (best matches were unrelated
genomics/LangGraph skills, score ≤33), and **the registry returned zero hooks** for
"format Go after edits", "run lint and tests before completing work" and "keep documentation
updated before committing". No registry MCPs or agents were installed. Re-run `/awos:hire`
interactively after the registry grows; this file goes stale as soon as `.claude/agents/` or
`context/product/architecture.md` changes.

**Provenance of the roster.** AWOS 1.5 (migration 2) removed the bundled domain-expert
directories (`.awos/subagents/`, `.claude/agents/domain-experts/`). The seven experts this project
had written there (audio-dsp, golang, llm, ml-audio, music-theory, strudel, python) were folded
into full standalone agents in `.claude/agents/` before the migration ran, with `skills:` bindings
to the project-local skills in `.claude/skills/`. The upstream bundles `kotlin-expert` and
`react-expert` were dropped (not part of this stack). `testing-expert` was added from the Citation
orchestrator's copy of the AWOS registry agent, with this project's pytest skills bound.

## Installed Hooks

| Name | Event | Command | Description |
| ---- | ----- | ------- | ----------- |
| session-init reminder | SessionStart (`startup\|clear`) | `echo '…'` | Points the session at `.claude/commands/session-init.md` unless the first message already names the work. Advisory. |
| branch-current | PreToolUse (`Bash`) | `.claude/hooks/branch-current.sh` | **Blocks** `git checkout -b`/`git switch -c` and `gh pr create` when HEAD is behind `origin/main`, and `gh pr merge` when the branch conflicts. Undetermined → allowed with a systemMessage. Override: `MIDIGREP_SKIP_BRANCH_CHECK=1 <cmd>`. |
| docs-freshness | PostToolUse (`Edit\|Write\|MultiEdit`) | `.claude/hooks/docs-freshness.sh` | Advisory, once per session: when a file under `internal/`, `cmd/`, `scripts/python/`, `scripts/node/src/`, `eval/` or `mcp_servers/` changes, reminds of the CLAUDE.md "Context Document Maintenance" rule and the BlackHole-only eval gate. |

All three are project-authored (modeled on the Citation orchestrator's hooks); none came from the
registry.

## Gaps

- **Go skill.** The registry has none (probed 2026-10-09), so `.claude/skills/go-cli-development/`
  was written locally from the golang-expert's patterns and bound to `golang-expert`.
- **Node recorder owner.** The Puppeteer/ffmpeg recorder is the only render path and has no agent.
  Either extend `audio-dsp-expert` or hire a TypeScript/Node agent bound to
  `typescript-development`.
- **UI verification.** `verify-ui` is now installed and bound to `testing-expert`, but `serve` has
  not yet been driven through it — the first web-UI change should.
- **Infra.** CI now exists (`.github/workflows/ci.yml`) but no agent owns it; Docker was retired
  (decision 2026-10-09, architecture.md §4) because a container can never run the macOS-only
  render path and the image had been broken since Feb 2026.
- **Registry hooks.** Searched 2026-10-09; the registry returned none. The project's own hooks
  (`branch-current.sh`, `docs-freshness.sh`) and the CI `go vet`/`gofmt`/pytest jobs cover the
  format-and-test guardrail instead.
